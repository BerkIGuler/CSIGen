\section{Overview}
CSIGen generates large wireless channel datasets with Sionna RT from a single YAML config. For a 3D city scene it places multi-sector base stations on the highest rooftops, samples users from a ray-traced radio map, traces the paths from every sector to its users, and saves per sector the channel frequency response (CFR), the paths, and the metadata needed to use and reproduce them.

\subsection{Quick Start}
Install the pinned dependencies (Python 3.12, Sionna RT 2.2.0; a CUDA GPU is strongly recommended) and run a config from the repository root:
\begin{minted}{bash}
pip install -r requirements.txt
python scripts/run.py --config config/examples/eval/la_config_test.yaml
\end{minted}
The run writes \texttt{output/<scene\_name>/<YYYYmmdd\_HHMMSS>/} with one \texttt{channel\_tx\_<t>.npz} per sector and a \texttt{metadata.yaml} (Section~\ref{sec:output}). Load a file with:
\begin{minted}{python}
import numpy as np
z = np.load("output/la_1/<run_id>/channel_tx_0.npz", allow_pickle=True)
h = z["h"]                       # [users, rx_ant, 1, tx_ant, ofdm_symbols, subcarriers], complex64
meta = z["metadata"].item()      # positions, LoS labels, path statistics, config, ...
\end{minted}
The example configs are in \texttt{config/examples/}: \texttt{pretrain/} at 3.5\,GHz and \texttt{eval/} at 28\,GHz, for the included scenes. To split a run into train and test runs, see Section~\ref{sec:splits}.

\subsection{Conventions}
\begin{itemize}
  \item \textbf{Names and indices.} Base station $b$ has sectors \texttt{BS\_<b>\_sector\_<s>}, $s = 1, \dots, N_s$ for $N_s$ = \key{num\_sectors}; their TX index is $t = b N_s + s - 1$, which numbers the output files. Users are \texttt{UE\_<k>}, numbered TX by TX: the users sampled for TX $t$ follow those of TX $t-1$.
  \item \textbf{Cells.} A \emph{cell} is a triangle of the measurement-surface mesh on which the radio map is computed (Section~\ref{sec:pipeline}), not a cell of the cellular network. The coverage area of a base station antenna is called a \emph{sector}.
  \item \textbf{Units.} Meters, seconds, Hz and radians, except for the config, which gives angles in degrees. Element spacings are in carrier wavelengths. Positions and angles are in the scene's global frame.
  \item \textbf{CFR scale.} \texttt{h} is the unitless channel gain (power gain $|h|^2$, about the path loss), not scaled by the TX power: \key{tx\_power\_dbm} enters only the radio-map metrics \texttt{rss} and \texttt{sinr} used for user sampling. The received power on a subcarrier is $P |h|^2$, or $P |\mathbf{h}\mathbf{w}|^2$ with a unit-norm precoder $\mathbf{w}$, for the transmit power $P$ you assign to that subcarrier. With \key{cfr\_normalize: true}, \texttt{load\_cfr(file, normalize=False)} recovers the unnormalized CFR from the saved paths, and \texttt{path\_stats} holds each channel's \texttt{path\_gain\_db}.
\end{itemize}

\section{Scenes}
\subsection{Generating a Scene}
Scenes are made with the \texttt{scenegen} tool of Geo2SigMap from a longitude/latitude bounding box (\href{https://bboxfinder.com}{bboxfinder.com} helps to pick one):
\begin{minted}{bash}
scenegen bbox -71.0602 42.3512 -71.0484 42.3591 --data-dir scenes/sample_scene --enable-lidar-terrain
\end{minted}
The folder gets \texttt{scene.xml}, which references \texttt{.ply} meshes under \texttt{mesh/} and stores the bounding box. Without \texttt{--enable-lidar-terrain}, the ground is a flat plane. CSIGen needs the scene's buildings, named \texttt{building\_<x>\_rooftop} and \texttt{building\_<x>\_wall}, and the terrain object \texttt{ground}, on which users are placed. Load scenes with \texttt{load\_scene(path, merge\_shapes=False)}; merged shapes lose the per-building objects.

\subsection{Materials}
\label{sec:materials}
Buildings and ground use ITU materials (mostly \texttt{concrete} and \texttt{metal}). The ITU ground models of the scene files (\texttt{wet\_ground} and others) are defined for 1--10\,GHz only, so above 10\,GHz set \key{override\_ground\_material}. All materials have Sionna's default scattering coefficient of 0, so the scenes produce no diffuse paths, even with diffuse reflection enabled.

\section{Configuration}
\label{sec:config}
A run is fully defined by one YAML file. All keys are required except those marked optional below; \texttt{load\_validated\_config(path)} (\texttt{src.config\_validator}) checks types, ranges and combinations before anything runs. A complete example:

\begin{minted}[frame=single, framesep=1mm, bgcolor=lightgray!20, linenos, label=config.yaml]{yaml}

# Scene setup

antenna_height_offset: 10.0       # BS antenna height above the rooftop (m)
num_deployment_buildings: 1       # number of base stations, on the highest buildings

terrain_clip_margin: 15.0         # margin around the buildings when clipping (m)
user_shift_from_ground: 1.5       # UE height above ground (m)
# override_ground_material: "asphalt_concrete"  # optional: "concrete" or "asphalt_concrete"

# TX (base station) array; RX (user) array with the same keys and rx_ prefix
tx_num_rows: 4
tx_num_cols: 8
tx_vertical_spacing: 0.5          # wavelengths
tx_horizontal_spacing: 0.5        # wavelengths
tx_pattern: "tr38901"             # tr38901, dipole, iso or hw_dipole
tx_polarization: "V"              # V, H, VH or cross (±45°)

# Base stations

mechanical_tilt: 10.0             # downtilt (degrees, positive = down)

tx_power_dbm: 43.0                # per sector; used for the rss/sinr sampling metrics only

# Radio map (user sampling)
radio_map_specular_reflection: true     # mirror-like reflections
radio_map_diffuse_reflection: false     # scattering from rough surfaces (needs a scattering coefficient > 0)
radio_map_refraction: true              # transmission through materials
radio_map_diffraction: true             # diffraction on building edges (wedges)
radio_map_edge_diffraction: true        # also on free-floating edges
radio_map_diffraction_lit_region: false # also where the direct path is not blocked
radio_map_max_depth: 5                  # maximum interactions per path

# User sampling
num_user_samples_per_tx: 200      # users per sector (at most)

  stationary_to_tx: {orientation_mode: "to_tx"}
  pedestrian:       {orientation_mode: "random", speed_distribution: "pedestrian", direction_mode: "random"}
  pedestrian_to_tx: {orientation_mode: "to_tx", speed_distribution: "pedestrian", direction_mode: "random"}
  vehicular:        {orientation_mode: "random", speed_distribution: "vehicular", direction_mode: "random"}
  slow_walking:     {orientation_mode: "random", speed_distribution: "uniform_continuous",
                     speed_min: 0.5, speed_max: 1.5, direction_mode: "random"}
  fast_walking:     {orientation_mode: "random", speed_distribution: "uniform_continuous",
                     speed_min: 1.5, speed_max: 2.5, direction_mode: "random"}

path_solver_max_num_paths_per_src: 10000000 # path buffer size per source
path_solver_samples_per_src: 10000000       # rays per source
path_solver_synthetic_array: true           # trace from array centres, add element phases
path_solver_los_mode: true                  # line-of-sight paths
path_solver_specular_reflection: true       # interaction toggles as for the radio map
path_solver_diffuse_reflection: false

path_solver_diffraction: true

\subsection{Reference}
Only what the comments above do not say is listed here.
\begin{description}
  \item[Scene setup.] \key{num\_deployment\_buildings} is the number of base stations (Section~\ref{sec:pipeline}). \key{override\_ground\_material} (optional) assigns \texttt{concrete} (1--100\,GHz) or \texttt{asphalt\_concrete} (1--40\,GHz) to the \texttt{ground} object and removes the wet-ground materials; without it, the scene's materials are kept.
  \item[Arrays.] All sectors share the TX array and all users the RX array (Sionna RT allows one of each per scene). \texttt{VH} and \texttt{cross} have two polarizations, so twice the elements. The antenna order is given in Section~\ref{sec:output}.
  \item[Interaction toggles.] The \texttt{radio\_map\_*} and \texttt{path\_solver\_*} flags (reflection, refraction, diffraction, depth, samples, seed) are separate, so the radio map, which only places users, can be cheaper than the path solve. See the \href{https://arxiv.org/abs/2504.21719}{Sionna RT technical report} for their meaning. Diffuse reflection has no effect with the included scenes (Section~\ref{sec:materials}).
  \item[User sampling.] \key{num\_user\_samples\_per\_tx} is a maximum: a sector with fewer valid cells gets fewer users, possibly none. The radio-map metric is per sector.
  \item[Mobility.] \key{mobility\_preset} must be one of the seven preset names shown. \texttt{orientation\_mode}: \texttt{random} (yaw uniform, pitch within $\pm 30^\circ$, roll within $\pm 45^\circ$) or \texttt{to\_tx} (the array faces the user's sector). \texttt{speed\_distribution}: none (stationary), \texttt{pedestrian} (0.5--2\,m/s), \texttt{vehicular} (8--30\,m/s) or \texttt{uniform\_continuous} between \texttt{speed\_min} and \texttt{speed\_max}; the direction is uniform in the horizontal plane. Users do not move during a run; the velocity only sets the Doppler shifts.
  \item[Path solver.] \key{path\_solver\_synthetic\_array: true} traces rays from the array centres only and adds the phase of each element analytically; it is much faster and required for the path data (Section~\ref{sec:paths}). \key{path\_solver\_per\_tx\_users\_only: false} solves every sector for all users of the scene, so each user appears in every sector's file. \key{path\_solver\_rx\_batch\_size} and \key{path\_solver\_spec\_table\_size} avoid silent path loss (Section~\ref{sec:pipeline}); their defaults are 50 and $4 \cdot 10^8$. Without a synthetic array, the table keeps Sionna's default ($10^6$), since every TX antenna is a source; batching then needs \key{cfr\_out\_type: numpy}, so with another output type the receivers are solved at once, with a warning. The validator rejects settings whose table indices exceed Sionna's 32-bit range: $\max(\textrm{table size}, \texttt{max\_num\_paths\_per\_src})$ times the number of sources (1 with a synthetic array, else the number of TX antennas) must stay below $2^{32}$.
  \item[CFR.] \key{cfr\_out\_type} (\texttt{numpy}, \texttt{tf}, \texttt{torch}, \texttt{jax} or \texttt{drjit}) applies only without a synthetic array, where Sionna computes the CFR; with batching it must be \texttt{numpy}.
  \item[Saved data.] \key{save\_paths} requires a synthetic array. With \key{save\_cfr: false}, the files hold only the paths, from which \texttt{load\_cfr} rebuilds the CFR exactly. At least one of the two must be true.
\end{description}

\section{How a Run Works}
\label{sec:pipeline}
\texttt{scripts/run.py} calls \texttt{generate\_channels(config)} (\texttt{src.channel\_generator}), which runs these steps.

\paragraph{1. Scene setup.} The scene is loaded at \key{carrier\_frequency}. With \key{clip\_terrain\_to\_buildings}, the ground is clipped to the bounding box of the buildings plus \key{terrain\_clip\_margin}, so that users are not placed in empty land around the city (Fig.~\ref{fig:scene_clip}). The clipped ground, raised by \key{user\_shift\_from\_ground}, is the measurement surface on which users are placed.

\paragraph{2. Base stations.} The \key{num\_deployment\_buildings} buildings with the highest centroids each get one base station, at the rooftop vertex closest to \key{scene\_center} (so that the building lies behind the antenna) and \key{antenna\_height\_offset} above the roof's highest point (Fig.~\ref{fig:antenna_placement}). Each base station has \key{num\_sectors} sectors at the same position, with azimuths $\key{azimuth\_offset} + 360^\circ (s-1)/N_s$ and the downtilt \key{mechanical\_tilt}; the orientation in Sionna's angles is $[\textrm{azimuth}, \textrm{tilt}, 0]$.

\paragraph{3. Radio map and user sampling.} A radio map over the measurement surface gives \key{user\_sample\_metric} per sector in every cell, a triangle of the surface mesh. A cell is valid for a sector if the metric lies within the thresholds, the cell centre lies within the distance limits and, with \key{tx\_association}, the sector is the strongest in the cell. Each sector takes up to \key{num\_user\_samples\_per\_tx} distinct valid cells (Fig.~\ref{fig:user_sampling} shows an example): every cell gets a random key from \key{user\_sample\_seed}, and the sector takes the valid cells with the lowest keys. The radio map is not bit-identical between GPU runs, and with this rule a cell that changes validity moves at most one user. Users are placed at the cell centres or, with \key{sample\_center\_pos: false}, at a random point of the cell.

\paragraph{4. Edge filtering.} With \key{scene\_edge\_epsilon} $> 0$, users within that distance of the bounding box of all sampled users are removed (Fig.~\ref{fig:edge_user_filter}). These users tend to be LoS-dominated. The filter acts after sampling, so a sector can keep fewer users than requested.

\paragraph{5. Receivers.} Each user becomes a receiver with the orientation and velocity of the mobility preset, drawn with \key{user\_sample\_seed}.

\paragraph{6. Path solving.} Each sector is solved alone, for its own users or for all users. Sionna RT stores each new chain of reflecting surfaces per receiver in a hash table of fixed size per source; when many receivers share one solve, the table fills up and new chains are discarded without a warning, so some NLoS paths can be lost (LoS paths are traced separately and are kept). CSIGen therefore solves the receivers in batches of \key{path\_solver\_rx\_batch\_size} with a larger table (\key{path\_solver\_spec\_table\_size}). It also records the largest fill of Sionna's path buffer (\texttt{path\_buffer\_fill}, as a fraction of \key{path\_solver\_max\_num\_paths\_per\_src}) and logs a warning when it reaches 1, that is, when candidate paths were discarded; there is no warning below that.

\paragraph{7. Valid channels and LoS labels.} A user without any path of positive delay has no channel to the sector and is dropped from its file. A kept channel is LoS (\texttt{los\_binary} = 1) if it has a path without any interaction.

\paragraph{8. Paths and CFR.} With a synthetic array, the paths of every kept channel are collected (Section~\ref{sec:paths}), and the CFR is computed from them. Without one, Sionna's \texttt{Paths.cfr} computes the CFR and no paths are saved. The results are streamed: \texttt{generate\_channels} yields one item per sector, and \texttt{run.py} writes its file before the next sector is solved.

\section{Output}
\label{sec:output}
\subsection{Files}
\begin{itemize}
  \item \texttt{channel\_tx\_<t>.npz}, one per sector $t$ (compressed): \texttt{h}, \texttt{shape} and \texttt{dtype} if the CFR is saved, the \texttt{paths\_*} arrays if the paths are saved (Section~\ref{sec:paths}), and \texttt{metadata}, a dictionary (load with \texttt{allow\_pickle=True} and \texttt{.item()}).
  \item \texttt{metadata.yaml}: CSIGen version, scene name, timestamp, number of sectors and users, users per sector, CFR shape and dtype per sector, CFR axes, array layouts, and the full validated config.
\end{itemize}

\subsection{CFR}
\texttt{h} is complex64 with axes \texttt{cfr\_axes} = (\texttt{rx}, \texttt{rx\_ant}, \texttt{tx}, \texttt{tx\_ant}, \texttt{ofdm\_symbol}, \texttt{subcarrier}): one row per kept user, a TX axis of size 1, and subcarriers ordered from the lowest to the highest frequency. The metadata \texttt{tx\_array} and \texttt{rx\_array} give each array's rows, columns, polarizations, spacing, pattern and antenna order: antenna $i = p\,R\,C + c\,R + r$ for row $r$ (from the top), column $c$ (along the array's local $y$ axis) and polarization $p$, with $R$ rows and $C$ columns. The vertical index therefore runs fastest; reshape an antenna axis to $[P, C, R]$ to get the array.

\subsection{Per-Sector Metadata}
Arrays marked ``per row'' are aligned with the rows of \texttt{h}.

\begin{center}
\small
\begin{tabularx}{\textwidth}{@{}lX@{}}
\toprule
Key & Content \\
\midrule
\texttt{tx\_idx}, \texttt{tx\_name}, \texttt{tx\_position}, \texttt{tx\_orientation} & the sector; orientation in Sionna's angles $[\alpha, \beta, \gamma]$ (rotations about $z$, $y$, $x$) \\
\texttt{rx\_names}, \texttt{rx\_positions} & per row: the user and its position ($[N, 3, 1]$) \\
\texttt{rx\_velocities}, \texttt{rx\_orientations} & per row: velocity (m/s) and orientation, $[N, 3]$ \\

\end{center}

\subsection{Python API}
\texttt{generate\_channels(config)} is an iterator with one dictionary per sector: \texttt{tx\_idx}, \texttt{tx\_name}, \texttt{h\_tx} (\texttt{None} with \key{save\_cfr: false}), \texttt{path\_data} (\texttt{None} without saved paths) and \texttt{tx\_metadata}. \texttt{save\_channel\_data} (\texttt{src.channel}) writes one item as a file.

\section{Path Data}
\label{sec:paths}
With a synthetic array, every path has one delay, Doppler shift and pair of directions for all antenna pairs, and CSIGen saves all valid paths of every channel. The paths of a file are stored in a flat layout: the paths of row $i$ are entries \texttt{paths\_offsets[i]} to \texttt{paths\_offsets[i+1]} $-\,1$ of the other arrays, sorted by power (the mean of $|a|^2$ over antenna pairs), strongest first. The metadata \texttt{path\_fields} describes each array.

\begin{center}
\small
\begin{tabular}{@{}lll@{}}
\toprule
Key & Shape and type & Content \\
\midrule
\texttt{paths\_offsets} & $[N+1]$ int64 & start of the paths of each row \\
\texttt{paths\_a} & $[P, N_\mathrm{rx}, N_\mathrm{tx}]$ complex64 & coefficient per antenna pair \\
\texttt{paths\_tau} & $[P]$ float32 & absolute delay (s) \\
\texttt{paths\_doppler} & $[P]$ float32 & Doppler shift (Hz) \\
\texttt{paths\_theta\_t}, \texttt{paths\_phi\_t} & $[P]$ float32 & zenith and azimuth of departure \\
\texttt{paths\_theta\_r}, \texttt{paths\_phi\_r} & $[P]$ float32 & zenith and azimuth of arrival \\
\texttt{paths\_interactions} & $[P, D]$ uint8 & interaction type per bounce \\
\bottomrule
\end{tabular}
\end{center}
$P$ is the number of paths of the file, $N_\mathrm{rx}$ and $N_\mathrm{tx}$ the numbers of antennas (in the order of the CFR) and $D$ = \key{path\_solver\_max\_depth}. The coefficients are passband, unitless and include the antenna patterns. Interaction codes: 0 none, 1 specular reflection, 2 diffuse reflection, 4 refraction, 8 diffraction; 0 also fills the bounces after the last, so a LoS path is all zeros. A path takes about $1/(N_\mathrm{sym} N_\mathrm{sc})$ of the size of its channel's CFR, so the paths of a channel with few paths (in our runs, medians of 3--11) take a few percent of the CFR; with thousands of paths, as from diffuse scattering, they exceed it.

\subsection{CFR from the Paths}
CSIGen computes the saved CFR from these arrays, in float64, with \texttt{cfr\_from\_paths} (\texttt{src.path\_data}), for every antenna pair:
\[
h(f, t) = \sum_{l} a_l \, e^{-j 2\pi (f_\mathrm{c} + f) \tau_l} \, e^{j 2\pi \nu_l t},
\]
with carrier frequency $f_\mathrm{c}$, subcarrier offsets $f$, time $t = n T$ of OFDM symbol $n$ (symbol duration $T = 1/\Delta f$ for subcarrier spacing $\Delta f$), delay $\tau_l$ and Doppler shift $\nu_l$. This is the formula of Sionna's \texttt{Paths.cfr}. \key{cfr\_normalize\_delays} first subtracts the earliest delay of each channel; \key{cfr\_normalize} scales each channel to unit average energy. The parameters are saved as \texttt{cfr\_params}.

Sionna computes the carrier phase $2\pi f_\mathrm{c} \tau_l$ in float32, so the CSIGen CFR differs from Sionna's by about 1\% at 28\,GHz and 0.1\% at 3.5\,GHz. Neither is more accurate, because the delays themselves are float32; the float64 computation makes the CFR exactly reproducible from the saved paths.

\subsection{Rebuilding and Modifying the CFR}
\texttt{load\_cfr(file)} returns the file's \texttt{h} bit for bit. Its arguments change the CFR without new ray tracing:
\begin{description}
  \item[Numerology.] \texttt{num\_subcarriers}, \texttt{subcarrier\_spacing}, \texttt{num\_ofdm\_symbols}, \texttt{normalize\_delays}, \texttt{normalize}, and \texttt{symbol\_duration} $T$, for example $1.07/\Delta f$ for a 7\% cyclic prefix.
  \item[Arrays.] \texttt{tx\_array} and \texttt{rx\_array} change \texttt{num\_rows}, \texttt{num\_cols}, \texttt{vertical\_spacing} or \texttt{horizontal\_spacing} (\texttt{retarget\_arrays}). With a synthetic array, the coefficient of an antenna pair is the centre coefficient times a plane-wave phase, $a_{l,mn} = a_l e^{j 2\pi (\mathbf{r}^\mathrm{rx}_m \cdot \hat{\mathbf{k}}^\mathrm{r}_l + \mathbf{r}^\mathrm{tx}_n \cdot \hat{\mathbf{k}}^\mathrm{t}_l)/\lambda}$, with element positions $\mathbf{r}$ rotated by \texttt{tx\_orientation} and \texttt{rx\_orientations} and the directions $\hat{\mathbf{k}}$ of departure and arrival. The centre coefficient is recovered from \texttt{paths\_a} and the phases of the new arrays applied. The element pattern, polarization and orientation cannot change, since the coefficients include them.
  \item[Velocities.] \texttt{rx\_velocities}, one velocity for all users (3 values) or one per row ($[N, 3]$), in m/s (\texttt{retarget\_velocities}). The scene and the sectors are static, so $\nu_l = \mathbf{v}^\mathrm{rx} \cdot \hat{\mathbf{k}}^\mathrm{r}_l / \lambda$, and the Doppler shifts are updated with the change of velocity. The users do not move, so this holds within a frame, not over distances in which the paths change.
  \item[Paths.] (\texttt{select\_paths}) \texttt{exclude\_interactions} drops paths with an interaction of the given types (\texttt{specular}, \texttt{diffuse}, \texttt{refraction}, \texttt{diffraction}); \texttt{max\_bounces} drops paths with more interactions (0 keeps the LoS path only); \texttt{power\_range\_db} drops paths more than this many dB below the strongest path of the channel; \texttt{max\_paths} then keeps the strongest remaining paths. A channel left without paths has a zero CFR; the normalizations apply to the remaining paths.
\end{description}
The array and velocity changes match new Sionna solves with the new settings to about $10^{-6}$ whenever the solves find the same paths.
\begin{minted}{python}
from src.path_data import load_cfr
f = "output/la_1/<run_id>/channel_tx_0.npz"
h = load_cfr(f)                                        # the saved h
h_64 = load_cfr(f, num_subcarriers=64)                 # 64 subcarriers
h_8x8 = load_cfr(f, tx_array=dict(num_rows=8, num_cols=8))
h_v = load_cfr(f, rx_velocities=[20.0, 0.0, 0.0])      # all users at 20 m/s along x
h_los = load_cfr(f, max_bounces=0)                     # LoS path only
\end{minted}

\subsection{Path Statistics}
\label{sec:stats}
The metadata \texttt{path\_stats} holds per-row arrays computed from all paths, also when the paths are not saved (only with a synthetic array). Spreads are power-weighted RMS values, azimuth spreads around the circular mean; angles are in the global frame.
\begin{itemize}
  \item \texttt{num\_paths}, \texttt{path\_gain\_db} (total power gain), \texttt{distance\_m} (3D TX--user distance);
  \item \texttt{first\_delay\_s}, \texttt{mean\_delay\_s}, \texttt{delay\_spread\_s};
  \item \texttt{k\_factor\_db}: LoS power over the power of all other paths (NaN without a LoS path, $+\infty$ with the LoS path only);
  \item \texttt{asd\_rad}, \texttt{zsd\_rad}: azimuth and zenith spreads of departure, at the sector (from \texttt{paths\_phi\_t}, \texttt{paths\_theta\_t}); \texttt{asa\_rad}, \texttt{zsa\_rad}: the same for arrival, at the user (from \texttt{paths\_phi\_r}, \texttt{paths\_theta\_r});
  \item the strongest path: \texttt{dominant\_power\_fraction}, \texttt{dominant\_tau\_s}, \texttt{dominant\_theta\_t}, \texttt{dominant\_phi\_t}, \texttt{dominant\_theta\_r}, \texttt{dominant\_phi\_r}, \texttt{dominant\_doppler\_hz}, \texttt{dominant\_num\_bounces};
  \item \texttt{max\_abs\_doppler\_hz}, \texttt{max\_num\_bounces};
  \item \texttt{power\_frac\_los}, \texttt{power\_frac\_specular}, \texttt{power\_frac\_diffuse}, \texttt{power\_frac\_refraction}, \texttt{power\_frac\_diffraction}: share of the power in the LoS path and in the paths with at least one interaction of each type (a path with two types counts for both).
\end{itemize}

\section{Train/Test Splits}
\label{sec:splits}
Each row of a file is the channel between one sector and one user, and with \key{path\_solver\_per\_tx\_users\_only: false} each user appears in every sector's file. \texttt{scripts/split\_dataset.py} assigns every channel to train, to test or to neither, so that train and test share no users, no sectors, or neither:
\begin{minted}{bash}
python scripts/split_dataset.py --run output/<scene_name>/<run_id> --out <out_dir> --by bs --test-ratio 0.2 --seed 1
\end{minted}

\subsection{Methods}
\begin{description}
  \item[\texttt{users}.] A random \texttt{--test-ratio} of the user positions is test, with all their channels. Train users can lie next to test users.
  \item[\texttt{area}.] The bounding box of the users is tiled with squares of \texttt{--block-size} meters (default 50), and random blocks are test until they hold at least the test ratio of the users (all but one block at most). With \texttt{--guard} $g$, train users within $g$ meters (horizontally) of a test user are dropped.
  \item[\texttt{sector}.] A random test ratio of the sectors, or those given with \texttt{--test-ids}, is test. Users appear on both sides. A test sector usually has train sectors on the same base station, which see the same paths with another orientation, so results are more optimistic than with \texttt{bs}.
  \item[\texttt{bs}.] As \texttt{sector}, for base stations with all their sectors (base station $b$ holds sectors $b N_s$ to $(b+1) N_s - 1$).
  \item[\texttt{sector+users}, \texttt{sector+area}, \texttt{bs+users}, \texttt{bs+area}.] A sector or base-station split and a user split, each with the test ratio $r$. A channel is train if its sector and user are both train, test if both are test, and dropped otherwise, so train and test share neither. With all users in every file, test keeps about $r^2$ of the channels and train $(1-r)^2$; use a larger ratio.
\end{description}
\texttt{--disjoint-users} makes a \texttt{sector} or \texttt{bs} split give each user the side of the sector it was sampled for (\texttt{rx\_serving\_tx}) and drop its channels to the other side. For \texttt{users}, \texttt{sector} and \texttt{bs}, the number of test items is the rounded ratio times the number of positions, sectors or base stations, at least one and at most all but one; sectors without channels are not drawn. Users at the same position, which runs before CSIGen 0.3.0 can contain, stay on one side. \texttt{--seed} fixes all random choices.

\subsection{Output}
\texttt{<out\_dir>/train/} and \texttt{<out\_dir>/test/} are runs in the usual format. Every sector file is written on both sides, restricted to that side's rows (possibly none), together with its per-row metadata, path statistics and paths; \texttt{source\_rows} gives each row's index in the source file and \texttt{split\_side} the side. \texttt{users\_per\_tx} and \texttt{total\_users} are renamed to \texttt{source\_users\_per\_tx} and \texttt{source\_total\_users}, and \texttt{metadata.yaml} gets \texttt{num\_users}. Each side's \texttt{split.yaml} records the method and all parameters, the chosen sectors, base stations or blocks (as indices $[i, j]$ from \texttt{block\_origin}), the users dropped by the guard or for a shared position, the source run, the CSIGen version, git commit, command and time of the split, and the channel and user counts per side and per sector.

\section{Reproducibility and Limitations}
\begin{itemize}
  \item \textbf{Determinism.} Sionna's GPU ray tracing is not bit-identical between runs: two runs of the same config can differ by up to about 1\% per channel, occasionally more when a path is found in one run and not the other, and a few radio-map cells near the thresholds can change validity. Each file records the config and the CSIGen version.
  \item \textbf{Precision.} Delays and angles are float32 (Section~\ref{sec:paths}).
  \item \textbf{Memory.} Without a synthetic array, every TX antenna is a separate source, which can exceed a 12\,GB GPU after a few sectors; the synthetic array avoids this.
  \item \textbf{Static scene.} Users have velocities but do not move; each channel is one snapshot of \key{num\_ofdm\_symbols} symbols.
  \item \textbf{Diffuse scattering.} The included scenes have no diffuse paths (Section~\ref{sec:materials}).
\end{itemize}
